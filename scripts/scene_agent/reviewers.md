# 独立审查章程(三个 SubAgent 会话)

通用规则(适用于每个审查会话):

- 每轮审查是一个**独立会话**:只读 `requirements.md` 与被审提案文件;不参考、不臆测其他审查会话的结论。
- 结论必须有证据:逐条检查表中引用提案**原文摘录**并给出分析,不得空泛表态。
- 判定:存在**任何一条主要问题(major)= fail**;次要建议(minor)不影响 pass。
- 本阶段审查的是**任务设计**,不要求场景 JSON、渲染或交互实现。
- 拿不准的事实按对提案不利的方式列为问题,不替提案补全借口。

## 审查一 research(研究契合度)

逐条核 `requirements.md` §1 与 §2:

1. 深度表 ≥3 个对象且沿视轴调焦距离差 ≥0.3m;depth_requirement ≥2 档;相机显式;"平面屏幕+HUD 等价性"的排除论证成立(若 HUD 能等价完成则 fail)。
2. inspect_back 步骤存在,且信息面被声明为径向面(可转台式查看)。
3. 任务脚本含:多步自然语言、消歧混淆项在交互清单内、颜色/位置属性、显式角度、打断-恢复、欠参数 clarify 用例、锚点类"再往里一点"不编造用例。
4. insert/assemble 锚点动作存在,锚点写在参照对象局部坐标。
5. 研究定义边界:无新机制、无 Gaussian 自由输出、σ/全息收益措辞为仿真演示假设。

## 审查二 realism(真实与实用)

逐条核 `requirements.md` §3:

1. **行业真实常见性**:该任务在该职业中每天/每周高频发生?执行方式(站位、工具、顺序)符合行业规程与习惯?
2. **深度冲突内禀性**:"近端精细操作 + 远端持续监控"是否被规程/工艺/安全要求所要求,还是摆拍出来的布局?
3. **猎奇排除**:是否属于罕见行业、新奇但非典型、影视化/灾难悬疑氛围?与 dig_site 类问题的距离?
4. **语汇真实性**:对象命名与指令措辞是否像该行业真实口语?
5. 场景对演示观众是否具备即时可理解性(不看解说能否明白在做什么工作)?

## 审查三 feasibility(工程可行与差异化)

逐条核 `requirements.md` §4 与 §5:

1. 交互对象 5–8 个、ID 合法、capabilities 属于合法枚举、能力负例 ≥2 条。
2. 锚点可写成参照物局部坐标;相机与调焦距离数值量级合理;坐标系约定(米制 Z-up、顺时针记负角)未被违反。
3. 资产可由程序化建模 + CC0 素材完成,工作量与现有 v2 场景同量级;环境对象与交互对象划分清晰。
4. 差异化标记与 §5 表中全部 9 个场景的任务图**结构上**不重合(逐个对比,域相似或结构相似都要指出)。
5. 提案结构完整(模板各节齐全,无缺项)。

## 报告格式

写入 `reviews/<scene_id>/round<N>_<role>.md`:

```markdown
# <scene_id> 第 N 轮 <role> 审查报告

- 审查人:独立 SubAgent(章程:<role>)
- 提案版本:vN
- 结论:pass / fail

## 逐条检查

| # | 检查项 | 结论 | 证据(提案原文摘录 + 分析) |
|---|---|---|---|

## 主要问题(fail 必填,pass 留空)

## 次要建议
```

最终回复只给一行:`VERDICT: pass` 或 `VERDICT: fail: <一句话最主要问题>`。
