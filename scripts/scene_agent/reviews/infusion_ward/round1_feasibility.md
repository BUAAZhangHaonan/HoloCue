## 主要问题

**M1(检查项 4,违反 §5 差异化要求):任务图结构与现有场景重合,差异化标记不成立。**

- 静态结构与 drone_bench「双 precise 连续步 + 遮挡查背面 + 远层读数监控」逐要素重合。证据(提案原文):「把新泵盒 PUMPCASSETTE 插进输液泵的 2 号泵槽 SLOT2,插好后把三通 STOPCOCK 顺时针拧 90 度打开,再核对一下 BAG1 背面的配置标签是不是 5% 糖,床头监护仪 MONITOR 全程盯着。」——插入(precise)+ 旋转(precise)连续两步、背面标签查证、远层读数监护,三要素与 drone_bench 标记一一对应;同时该结构完整包含 server_rack「单 precise 精插 + 深处查背面 + 远层告警监控」及 engine_bay 的 rotate+insert+inspect_back 三元组。§5 明示「域不同不等于结构不同」,换到医疗护理域不解除重合。
- 声称的差异化要素「本场景的事件源为脚本时间线报警,构成"设备事件抢占-恢复"的结构」未在任务脚本中实现为设备事件驱动:两处打断触发均为用户口语(「先停下,监护仪血氧报警了,先看 MONITOR,泵的事保留」;测试输入「血氧又响了先看监护」),脚本时间线仅让 MONITOR「报警时黄色闪烁」作为视觉背景。这与提案自己用来对比的「engine_bay/drone_bench 的打断由用户口语发起」结构完全相同;打断-恢复是 §2.3 对所有场景的必备解析语义,不构成结构差异。若意图是让报警事件本身直接进入重规划管线(不经用户口语),提案未写明该机制,且需另行论证其不属于研究定义之外的新机制——按章程,拿不准处按对提案不利处理。

**M2(检查项 2,违反 §4「相机与调焦距离数值量级合理/结构合理性」):相机、锚点世界坐标与深度表自相矛盾,给定几何下中层深度不可分离。**

- 提案给定「camera_position_m=[0.55,-1.25,1.42]」「SLOT2……世界位约 [-0.05,0.12,1.18]」;按此实算,SLOT2 沿视轴距离 ≈1.51m(径向距离同 ≈1.51m),而深度表近层写「≈1.0m」,偏差约 0.5m(50%),提案内部数值互斥,超出"设计初值只查量级"可容忍的范围。
- 更结构性:SLOT2/STOPCOCK/BAG1 同挂一根输液架、仅沿高度分布(z≈0.95/1.18/1.75),而视线接近水平(视轴方向 z 分量 -0.111),高度差沿视轴最多贡献 0.09m;实算三对象沿视轴为 1.45/1.51/1.54m(即使袋挂钩背向相机外伸 0.3m,BAG1 也仅 ≈1.7m,与 SLOT2 差 <0.3m)。因此表中「沿视轴调焦距离 1.0 / 1.6 / 2.2m,相邻差 0.6m(≥0.3m)」的三层分离在提案自己的相机与布局下几何上不可能成立:修正后近/中近/中三层挤在 ≈1.5m 附近,「≥3 个沿视轴 ≥0.3m 分离对象」只剩"车上泵盒(约 1m)—架体簇(约 1.5m)—监护仪(约 2.2m)"一种重述,与提案表列的四层结构不符。需给出自洽的相机/站位/深度表,或改变"中"层对象的空间来源(不能只改数字,同一立架上的垂直分布换不来 0.3m 沿轴间距)。

## 次要建议

1. 泵体(挂架上的单通道输液泵壳体)应明确列入环境清单或交互对象表,当前两处均未包含,环境/交互划分留有缺口。
2. 深度表小结句「沿视轴调焦距离 1.0 / 1.6 / 2.2m」只挑了三行,漏掉 STOPCOCK 的 ≈1.1m(与近层仅差 0.1m);建议表明示由哪些对象承担 ≥0.3m 分离,避免选择性摘录。
3. 相机高度 1.42m 略低于站立护士典型眼高(约 1.5–1.6m),定稿建模时校准。
4. 「连续快速发两条指令 → epoch 竞争」引用的是项目既有重规划/epoch 语义,建议在提案中注明,避免被读作本场景新增机制。
