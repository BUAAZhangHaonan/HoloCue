# 提案 `infusion_ward`:病房输液泵装管与床头监护(v2)

护士在普通病房床旁完成一次输液准备:近端把泵盒插入泵槽,抬头核对高处挂袋背面的配置标签,确认无误后才拧开三通开始输液,远端床头监护仪全程盯数值。**差异化标记**:**depth_requirement 全三档同场主链**(precise 插入 / persistent 核对与监护 / neutral 在链三通旋转)+ **设备报警事件驱动的「background 提升 current → resume 恢复」闭环**。

与现有场景的结构对比(逐个):
- drone_bench 是「双 precise 连续步」;本场景主链仅一条 precise(泵盒插入),三通旋转为 neutral 档。
- server_rack 的 rotate(FAN)与 neutral(dig 的 TROWEL)均只在扩展用例出现;本场景 neutral rotate 在初始主链内,且主链覆盖 precise/persistent/neutral 全三档。
- server_rack 的告警仅为「暂停」语义、其打断由用户自主选择对象;本场景的打断源是脚本时间线上的监护仪报警,抢占对象是 background 监控对象本身(MONITOR 由 background 提升为 current/wait),处理后 resume 恢复原队列——完整闭环未被任何现有场景覆盖。

## 修订记录(v1 → v2)

round1 审查(major):① realism——v1 把标签核对安排在三通开放(给药)之后,违反护理查对制度「先核对后给药」;② feasibility——差异化标记与 drone_bench 重合,且相机/深度表数值实算矛盾(SLOT2 沿视轴实为 ≈1.51m,三对象挤在 1.45–1.54m)。v2 修正:任务时序改为「插泵盒(机械准备)→ 核对标签 → 确认后开三通(给药)」;三通降为 neutral 档并在差异化段落逐场景对比;全部坐标与沿视轴距离按 |(P−C)·d̂| 重算,自洽。

## 世界

医院普通病房单床单元。病床靠墙,床侧立输液架:架上部挂两袋同规格糖水(BAG1 已挂待开放、BAG2 备用,配置标签均贴在**袋背面**),架中部挂单通道输液泵,泵正面 2 号泵槽(SLOT2)空置、槽口朝向护士;泵下管路串有三通旋塞(STOPCOCK,手柄横向为关闭)。床旁治疗车顶层放着全新一次性泵盒(管路预装)。床头墙面挂多参数监护仪(心率/血氧,报警时黄色闪烁)。护士站位:治疗车—输液架—床头近似成一线。站位与纵深由护理操作规程决定:装管与核对面对泵和挂袋,而「输液期间持续留意监护」是病房护理的常规要求——近操作与远监控在同一步流程里并存;查对制度要求给药(开放三通)之前完成标签核对。

## 视点与深度

`camera_position_m=[0.40,-1.05,1.45]`,`camera_look_at_m=[-0.15,0.55,1.35]`(设计初值)。沿视轴距离按 |(P−C)·d̂| 计算,下表与所给世界位坐标自洽(建模定稿后以 `scenes/<id>/scene.json` 实测为准)。

| 层 | 对象 | 世界位概要(设计初值) | 沿视轴距离 | task_role / depth_requirement | N/σ 倾向 |
|---|---|---|---|---|---|
| 近 | PUMPCASSETTE→SLOT2 泵盒插入 | [0.05,0.15,1.18] | ≈1.26m | current / precise | 高 N,小 σ |
| 近(步骤,非独立层) | STOPCOCK 三通顺时针 90° 开启 | [0.10,0.20,0.95] | ≈1.31m | next / **neutral** | 中 N,中 σ |
| 中 | BAG1 糖袋背面配置标签 | [-0.05,0.55,1.80] | ≈1.64m | next / persistent | 中 N,大 σ |
| 远 | MONITOR 床头监护仪 | [-0.35,1.35,1.60] | ≈2.50m | background / persistent | 低 N,大 σ |

沿视轴调焦距离 1.26 / 1.64 / 2.50m,相邻层差 0.38 / 0.86m(≥0.3m);depth_requirement 覆盖 precise / persistent / neutral 三档(≥2 档)。

## 任务脚本

- 初始指令:`把新泵盒 PUMPCASSETTE 插进输液泵的 2 号泵槽 SLOT2,插好后核对 BAG1 背面的配置标签是不是 5% 糖,确认无误再把三通 STOPCOCK 顺时针拧 90 度开始输液,床头监护仪 MONITOR 全程盯着。`
- 打断(报警事件驱动):`先停下,监护仪血氧报警了,先看 MONITOR,泵的事保留。` → interrupt:MONITOR 由 background 提升为 current(wait),装管队列挂起;`报警处理完了,继续开三通。` → resume,恢复挂起队列。(监护仪报警为确定性脚本时间线事件——状态在约定时刻翻转,非感知网络、非 LLM 输出。)
- 扩展测试输入:

| 输入 | 检查点 |
|---|---|
| 把那袋糖翻过来看下标签 | BAG1/BAG2 同型在清单 → 指代不明,clarify |
| 把三通拧一下 | 有 rotate 缺角度 → clarify,不编造 0 度 |
| 把泵盒再插深一点 | 锚点终点唯一 → interrupt 按既有 SLOT2 锚点演示,不改终点 |
| 把 MONITOR 转过来 | MONITOR 无 rotate → 校验拒绝 |
| 把糖袋转 30 度 | BAG1 无 rotate → 校验拒绝 |
| 血氧又响了先看监护 | 事件驱动 interrupt;epoch 竞争仅最新可提交 |
| 报警处理完了继续 | resume 语义,挂起队列恢复、顺序不变 |
| 连续快速发两条指令 | epoch 竞争,仅最新 epoch 可提交 |

## 环境

病床与床头柜、输液架底座与挂钩、治疗车、病房墙地(常规 PBR)、隔帘、呼叫按钮(程序化建模为主;管路与袋体半透明材质程序化生成)。

## 为什么强契合

1. **焦深分层必要性**:装管(1.26m)对准泵槽、核对标签(1.64m)抬头看挂袋、监护(2.50m)再抬眼到床头屏——三档调焦距离是护理流程本身要求的顺序切换;平面屏幕+角落 HUD 无法同时保留「泵槽对准」与「床头读数」两个焦面,注意资源会被 HUD 挤占。全息收益现阶段为仿真演示假设,由后续对照实验测定。
2. **遮挡与背面信息**:配置标签贴在袋背面,袋体朝护士一面只能看到药液;半透明 ghost 副本绕局部 Z 转 180°(转台式)展示标签面,袋体贴面为径向面,符合建模约定。
3. **LLM 解析必要性**:指令含「2 号泵槽」编号指代、BAG1/BAG2 同型消歧、「顺时针 90 度」显式角度(fixture 记 -90)、「全程盯着」持续性、报警打断-恢复;缺角度与指代不明输入必须 clarify;「再插深一点」按锚点 interrupt 不编造。
4. **空间锚定动作**:PUMPCASSETTE 插入终点由 SLOT2 局部坐标 insertion 锚点唯一决定;ghost_motion 演示结束不等于操作完成(用户确认完成才推进)。
