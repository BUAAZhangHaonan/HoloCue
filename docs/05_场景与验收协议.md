# 场景与验收协议

## 共用条件

三个场景均使用米制右手坐标、Z 向上；旋转角度以对象局部 Z 轴为正轴，逆时针为正。场景对象及能力由 JSON 提供。第一阶段模型输入条件为已知场景清单，可选图像接口用于后续视觉测试。当前固定池与 σ 档位属于演示配置，预算算法名称在配置中明确标为 baseline。

## 场景一 旋钮与背面检查

A 和 B 是旋钮，C 是带背面定位结构的模块。先输入“把 B 逆时针转 30 度，接着检查 C 的背面。”B 获得当前提示，C 获得后续提示。

动画运行中输入“先别管 B，看看 C 的背面，保留 B 的角度。”旧动画停止，C 切到当前任务，B 的 task_id、角度和后续步骤一起挂起。确认临时检查完成，再输入“继续刚才 B 的任务。”原来的 B 步骤恢复，角度仍为 30 度，task_id 不变。

演示背面使用 C 的半透明几何副本旋转，真实场景对象的位置和朝向保持不变。这个副本是指导动画。用户操作状态由显式确认更新。

## 场景二 插头空间对准

P 是蓝色插头，S 是插座，C 是备用模块。输入“演示把 P 插进 S，插好后再检查 C。”显示 P 的三维副本沿已知插入方向移动，终点由 S 的 insertion 锚点决定。暂停时副本停止，恢复时沿现有任务继续。原始实体 P 不被动画搬走。

## 场景三 积木分步搭建

A 是黄色积木，B 是蓝色积木，BASE 是绿色底板。输入“先把 A 放到底板 BASE 上，然后检查 B 的背面。”A 的显示副本朝 placement 锚点移动，B 保留下一步提示。验收对象选择、先后顺序和参数更新。

## 扩展测试输入

| 输入 | 检查点 |
|---|---|
| 暂停一下，先别继续 | 立即停止旧动作，保存当前步骤 |
| 继续刚才没做完的那步 | 正确恢复现有状态，不从头创建重复任务 |
| B 先逆时针转 15 度，之后再看 A | 角度与对象顺序正确 |
| 别转了，先检查 C 的背面，回头还要接着做 B | 嵌套任务和原参数保留 |
| 把刚才临时检查的任务结束掉 | 临时任务完成，不误删挂起计划 |
| 这个旋钮转一点 | 信息不足时请求说明角度，不猜测 |
| 把不存在的 Z 转 30 度 | 语义澄清或严格拒绝未知对象 |
| 把 C 转 30 度 | C 未声明 rotate 能力，输出须被校验 |
| 显示 C，先保留 B 的操作参数 | 语义与状态一致 |
| 新建任务，把 A 放到底板上 | replace 的范围明确，旧队列变更有日志 |
| 在第一条请求尚未返回时连续发送第二条 | 只有最新 epoch 可以提交 |
| 模型服务断开时发送指令 | 界面可见错误，动作冻结，绝不回放假答案 |

对自由语言测试保存所有尝试，包括失败。提示词修改前后分开计数。首次闭环以功能正确为验收目标，响应时间报告实测中位数、尾部与样本数；网页刷新频率、模型响应和 CGH 帧率分别命名。

## 必需证据

三个真实 Viser 场景截图；三个 Blender 实际生成截图；一段打断与恢复录像或完整带时间戳帧序列；一次 Blender 与 Viser 使用同一 session_id 的比对；live 原始模型请求与响应；任务快照与事件日志；进程与 GPU 记录。画面中保留 live 或 replay 和语义预览标记。
