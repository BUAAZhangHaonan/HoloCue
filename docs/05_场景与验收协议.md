# 十二场景验收协议

当前场景列表、任务与观察重点见 [场景约定](SCENE_REVIEW.md)，执行命令与证据要求见 [验证标准](VALIDATION.md)。每个 `scenes/<id>/scene.json` 提供初始输入、完整有序步骤、常驻目标与临时检查输入。

## 核心任务检查

核对真实模型输出的目标、动作、接收对象、角度与顺序。同一对象的旋转与后续检查分别保留。临时任务完成后恢复原任务标识、参数与进度，逐步完成直到原队列清空，并核对实体最终位姿。

控制面板路径必须包括 B 逆时针转 30 度、临时检查 C、明确完成 C、恢复 B。恢复后 B 的 task_id 与角度保持一致。暂停和临时打断保留动作进度，动画到达终点后等待用户确认。

## 几何与显示检查

旋转轴、支点、接合坐标系和检查面来自共同场景契约。插入与放置必须经过真实开口，避开支架、机壳、桌面和无关对象。观察实际模型的端子、标签、底部套筒、拉钉和减震垫。

十二场景分别保存 Blender 原生图像、Viser 宽屏和较窄窗口图像、操作特写、检查面及同会话桥接证据。视频或完整帧序列覆盖起点、动作、终点等待、临时检查与恢复。固定暂停状态改变焦点与亮度，核对画布像素与实际三维提示的响应。

## 并发与错误检查

两个独立浏览器上下文分别使用不同场景与会话，改变相机、焦点和任务时互不影响。检查快速连续指令、模型请求中断、API 重启、过期显示数据、模型连接失败与恢复后的显式继续。错误须可见，旧动作不得继续执行。

模型原始请求与回复、全部尝试及失败、任务快照、事件、版本、资源记录和执行命令保存到本次验收目录。提示词修改前后的结果分别记录。三份独立审查对应同一最终代码摘要，并明确列出实际检查过的证据。
