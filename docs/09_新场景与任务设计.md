# 场景与任务设计入口

十二个场景的当前任务、操作部件和检查重点见 [场景约定](SCENE_REVIEW.md)。每个场景的 `scenes/<id>/scene.json` 保存对象与环境、尺寸、位姿、动作能力、接合坐标系、检查面、相机以及 `task_contract`。

## 场景契约

模型依据场景对象描述和用户输入生成语义任务。评价端使用 `initial_instruction` 与 `task_contract` 中的 `ordered_steps`、`persistent_targets` 和 `interrupt_instruction` 核对实际输出；任务契约不作为模型固定答案。

旋转使用对象声明的轴与支点。插入或放置的终点由目标接合坐标系与源接合坐标系计算，运动路径经过真实开口。检查面对应实际模型结构，包括背面端子、标签、底部空腔、拉钉或减震垫。相机根据任务对象、网格边界、检查面和窗口比例确定观察范围。

对象可以先旋转再检查；这两个步骤在计划中独立保留。动画结束等待用户确认，明确完成后更新实体位姿。临时任务完成后恢复原任务标识、参数和动作进度。

## 构建与验收

统一资产实现位于 `src/holocue/modeling.py`，资产构建入口为 `scripts/scenes/build_simulation_assets.py`。原生 Blender 构建使用 `scripts/scenes/build_all.sh`，所有场景由配置目录枚举。已有有效精细结构、许可与来源保留。

每个场景检查工作区域、操作特写和结构检查。视觉审查覆盖比例、硬边与圆角、空腔、支撑结构、材质反射、标签纹理和近距离可读性。原生验收同时覆盖 Viser、Blender、两种窗口尺寸与同会话动作。

解析 Gaussian 参数来自 `configs/preview_response.json`，显示响应的科学范围见 [系统架构](SIMULATION_ARCHITECTURE.md)。场景交互结果与物理光学实验分别记录；实际验收情况以新建运行目录中的证据为准。
