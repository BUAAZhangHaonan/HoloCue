# 新场景与任务设计(扩展轮,评审修订版)

本文件定义五个全新场景的任务设计。设计基准来自 `docs/01_HoloCue_论文思路与系统总览.md` 的核心命题:**任务驱动的全息焦深提示**——LLM 把自然语言任务解析为对象、动作、任务角色、优先级与深度需求,确定性模块据此独立映射 Gaussian 数量 N(←priority)与 σ 档位(←depth_requirement),全息显示在焦深上分层呈现"当前精扫 / 下一步预览 / 背景常驻"。

修订记录:2026-09-17 依两份独立评审(研究契合度 + 代码契约可行性)重写。主要变化:判据 1 度量改为**沿主视轴的调焦距离差**并要求显式相机声明;`watch_service` 因违背自身判据(无 inspect_back 步骤、深度差 0.04m、cue 几何压垮 3cm 物体)整体替换为 `optical_bench`;全部锚点改按**参照对象局部坐标系**书写;全部"假歧义" clarify 用例修正为真歧义(混淆项进入交互对象表);σ 与 priority 的耦合措辞解耦;过度物理声明降格为可检验假设。

## 设计判据(每个场景必须同时满足)

一个场景只有同时满足以下四条才算"非常符合要求",仅沾边者不进入建模:

1. **焦深分层必要性**:任务天然包含 ≥3 个**沿主视轴方向调焦距离差 ≥0.3m** 的关注对象,且 depth_requirement 覆盖至少两档(precise/persistent/neutral 中 ≥2 档)。每场景用 `camera_position_m`/`camera_look_at_m` 显式声明视点,深度表给出沿视轴的近似调焦距离。若一块平面屏幕加高亮/角落 HUD 指示就能等价完成,该场景不合格;全息的优势假设是"提供与屏幕平面正交的调焦轴,使不同深度的提示可同时保留且互不遮挡",该假设的收益由后续对照实验测定,本阶段为仿真演示。
2. **遮挡与背面信息**:存在"必须查看被遮挡区域或背面"的步骤(inspect_back),演示用半透明副本 180° 绕局部 Z 轴旋转(转台式)。**建模约定**:inspect_back 对象的信息面必须是径向面(随 Z 转动能转到朝向相机的一面),不得是纯顶/底面。
3. **LLM 解析必要性**:指令是自然语言多步任务,含指代消解(混淆项必须是交互对象、会进入 LLM 清单)、颜色/位置属性、显式角度参数、打断-恢复语义;欠参数输入必须触发 clarify 而非编造。锚点类动作(插入/放置)的终点由场景锚点唯一决定,故"再往里一点"类输入按既定锚点做 interrupt 演示,不 clarify、不编造新终点——此为固定验收口径。角度类输入缺角度必须 clarify。
4. **空间锚定动作**:至少一步 insert/assemble,终点由参照对象的 insertion/placement 锚点(局部坐标)决定,展示 ghost_motion 演示与"演示≠完成"原则。

通用约定沿用初版三场景:米制、Z 向上、右手系;rotate 以对象局部 Z 轴为正、逆时针为正(顺时针输入在 fixture 中记为负角);锚点书写在**参照对象局部坐标系**(见 `src/holocue/projection.py` 的 goal 计算式);交互对象能力与锚点写入场景 JSON;环境对象进入新增的 `environment` 列表(仅渲染,不进入 LLM 提示词与校验);每场景附带扩展测试输入表。扩展场景的 Viser 视图默认开启 `render_hints.fit_camera`(按场景包围盒自动适配透视取景),Blender 正交取景以场景 JSON 的 `ortho_scale_m` 为准,两者口径差异属预期。

N/σ 映射提示:各深度表的"N/σ 倾向"列仅表述两条**独立**规则的方向——N 随 priority 升高、σ 档位随 depth_requirement(precise 小 / persistent 大 / neutral 中间),不存在"N 高所以 σ 小"的直接耦合。

## 场景分册索引

五个场景的完整设计随场景套件维护：`scenes/<id>/docs/design.md`（server_rack / drone_bench / shelf_picking / optical_bench / dig_site）。本文件保留四判据总纲、与初版三场景的关系、验收要点；各场景的世界、视点与深度表、任务脚本、交互对象表、环境清单以分册为准。

## 与初版三场景的关系

初版三场景(旋钮/插件/积木)验证接口闭环;扩展五场景在完全不同的世界(机房/维修台/仓储/光学台/田野)复用同一 schema、同一 planner 提示词、同一 N/σ 策略,不改变研究定义。扩展场景沿视轴调焦距离差为 0.4–1.7m(视点声明见各场景),对象数 5–8(含消歧项),均高于初版。五场景任务图刻意差异化:单 precise+深查(rack)、双 precise(drone)、双 background+同深度角色对照(shelf)、跨层内禀注意+光学主题(bench)、非插入类 current+neutral(dig)。

脚本化事件说明:rack 的 ALARM 变色、shelf 的 GREEN 到位属于确定性脚本时间线(环境事件来源为脚本,非感知网络、非 LLM 输出),用于后续 e2e 验证"背景层提示动态更新";本轮按用户要求不跑端到端,仅设计记录。

## 验收要点(每场景)

1. 场景 JSON 通过扩展后 `SceneSpec` 校验(含 environment/render_hints 可选字段);锚点为参照对象局部坐标且满足 insert/assemble 校验;对象能力与任务脚本、扩展测试表一一对应(含能力负例)。
2. Blender 渲染 ≥1280×900(按各自 render_hints 取景),**三轮独立视觉审核**通过:几何正确性(对象可辨、锚点几何合理)、任务可读性(深度分层与角色在画面中可辨)、美观与丰富度不低于初版水平。
3. 环境资产来源与许可记录于 `assets/downloads/`(PolyHaven/ambientCG,CC0)与 `assets/ASSET_LICENSE.md`;加工后资产集中于 `assets/meshes/env/`。
4. 交互证据(Viser 截图、打断-恢复帧序列、live 模型原始输入输出)本轮按用户要求不跑端到端,留待下一轮;本表仅锁定场景与任务的可执行性设计。
