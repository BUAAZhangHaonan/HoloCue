# Viser 相机运行协议

`runtime_camera_v1` 使用现有场景网格、交互、Gaussian 分配与真实 Qwen3.5-4B，默认播放速度 1.0。日常任务不启动 Blender、VTK 或原生桥接。Blender 用于离线建模、导出 GLB 和原生外观/几何复核；Viser 的 WebGL 客户端负责实际三维绘制。任务状态与运动学在 HoloCue Python 服务中，Viser 本身不是接触动力学引擎。

## 图像与相机

默认 `HOLOCUE_OBSERVATION_MODE=camera_rgb`。每次“发送任务”在提交时冻结会话、revision、epoch、实体位姿、动作时钟及相机，然后调用 `ClientHandle.get_render()` 获取真实场景 RGB。模型请求包含这一张 PNG 与既有结构化对象/任务上下文。几何仍由确定性模块计算，不能把这个混合输入协议称为纯视觉识别实验。

图像不含页面侧栏、按钮等 DOM 控件；Viser 场景标签、模型内文字纹理与三维提示正常参与渲染。使用实际相机的米制位姿、四元数、视场角、near/far 和投影宽高比。输出最长边 1024，取整后的像素尺寸及内参随图像保存，投影宽高比不被整数像素比替代。PNG 的不透明 alpha 经校验后去除，RGB 不再压缩或重绘；仍执行既有 1.5 MB 输入限额，超限或资源错误直接失败。

客户端需有正常工作的硬件 WebGL。取图接口由 Python 发起，绘制在连接的浏览器客户端完成；这是 Viser 的相机渲染接口，不能宣称为无浏览器的服务端渲染器。若模型在远程服务器，浏览器可以在工作站通过 SSH 连接。检查实际 `WEBGL_debug_renderer_info`，不能把启动参数或 `/dev/nvidia*` 存在当成硬件加速证据。

冻结期间停止该会话的显示时钟与场景更新，并在锁外等待图像，避免阻塞网络/相机回调。窗口变化推迟至本次捕获结束处理。客户端检查当前可见 GLB 的挂载与纹理解码、环境贴图安装、Gaussian 当前缓冲和排序器；不采用固定等待、连续截图“像素稳定”或失败后的纯文本兜底。

每张观测保存在 `$RUN_DIR/viewer/observations/<session_id>/`，含 PNG 与 JSON：用途、状态版本、相机参数、实际实体位姿、提示显示参数、时钟、图像摘要、资源路径和捕获耗时。模型的原始 HTTP 请求/回复保存在 API job/event 中，可用图像摘要验证模型确实收到对应帧。“观察 → 采集相机图像”可额外保存同一接口的图像。

## 运行与录像

先按 README 启动模型、API 和 Viser；正常任务只需要这三个服务。观测默认启用，也可明确传参：

```bash
bash scripts/run_simulation.sh viewer --scene-set reconstructed --observation-mode camera_rgb
```

`text_state` 明确用于重放既有纯文本协议；其模型未收到图像，不得混入 `runtime_camera_v1` 的结果。原有 `audit_bridge_live`、原生场景构建与 Blender 对照属于单独的离线审计入口，方法、参数和旧数据保留。

`scripts/tests/runtime_camera.py` 每批仅接受一到两个场景，连接已启动的真实硬件浏览器 CDP。运行端应与 API/Viser 的 `$RUN_DIR` 相同，便于读取该会话的实时显示时钟。例如浏览器在本机通过本地 18780 转发远程 8780，CDP 反向转发到服务器 19222：

```bash
"$APP_PYTHON" scripts/tests/runtime_camera.py \
  --cdp http://127.0.0.1:19222 --viewer 'http://127.0.0.1:18780/?fixedDpr=1' \
  --api http://127.0.0.1:8750 \
  --scenes dive_fillstation dig_site --out "$RUN_DIR/batch_01"
```

所有状态修改通过真实界面完成。逐场核对主步骤、持续背景、动作途中暂停、临时检查、原 task_id/参数/时钟恢复、逐步骤显式完成及最终空队列。模型正常调用两次（主计划和打断），恢复通过产品已有按钮完成。每场必须完成全部步骤，不以任务请求成功或第一段动画作为完成。

测量入口通过 Viser 已有的 `fixedDpr=1` 参数固定渲染像素比，防止自适应 DPR 在录制中改变像素尺寸；这与浏览器 deviceScaleFactor 是不同设置。录像从真实 WebGL 场景帧复制到独立录制画布，使用 MediaRecorder 的真实时间戳。取图期间暂时改变的渲染缓冲不进入录像；录像保持最后正常画面及真实等待时间。记录实际帧数与时间间隔，不把采集上限称为实际帧率，不用固定帧率重组图片或加速视频掩盖等待。

## 耗时口径

- 冷启动：模型加载、服务启动与首个场景/材质/相机就绪，单列报告。
- 在线任务：从首次发送按钮点击之前，到最后一个步骤明确完成且状态同步。包含首张输入图、两次模型推理、动作、暂停/打断/恢复、验证图像及控制等待。目标每场不超过 180 秒。
- 收尾：最终图像导出、录像封装和原始记录落盘，另列且保留录像的实际墙钟时长。
- 离线原生审计：Blender 资产加载、多层 Gaussian Cycles 渲染和同视角复核，单独报告，不计入在线交互耗时。

旧版原生桥接完整录像包含等待离线 Blender 与浏览器截图的时间，并以 0.1 倍动作速度采集。它们不能用作 1.0 倍正常交互的完成时间。新旧数字的流程不同，不能表述为同协议算法加速比。
