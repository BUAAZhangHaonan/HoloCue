# 第一阶段执行计划

## 交付目标

在 4029 的项目目录中建立真实 Qwen 后端、持久任务状态和 Blender 加 Viser 的三场景交互原型。一次完整路径包括下达任务、显示当前与后续提示、自然语言打断、确认临时任务、恢复原参数，以及导出版本化显示包。

## 阶段 0 只读盘点

核对工作目录、现有 Git 文件和未提交修改。读取系统内存、磁盘、物理 GPU 1、2 的型号、显存、占用和 UUID；查询现有 Blender 版本与路径。运行 `scripts/inspect_server.py` 保存到 `runs/server_inventory.json`。检查既有服务器红线。盘点 4029 现有模型，再用已配置 SSH 只读查找 4028 Models。资源阈值记录后再启动任务。

## 阶段 1 应用与资产

在 `.venv` 安装应用依赖，使用 Python 3.11 或 3.12 的兼容环境并记录实际版本。运行测试与 Bash 语法检查。打开 GLB 资产检查尺寸、颜色和方向。复用已有 Blender，以 CPU 构建三个 `.blend`，渲染三个真实场景预览。GLB 和 JSON 已提供，资产重生成脚本会改写基线清单，已有编辑时不要直接覆盖运行。

## 阶段 2 显式回放联调

使用 `HOLOCUE_MODE=replay` 检查网页、按钮、挂起状态、动画和参数变化。截图必须保留 replay 标记。这一阶段排除 UI 和状态层问题，结果单独保存，不计入模型成功率。Viser 目标循环频率为 30 Hz，先测实际情况。

## 阶段 3 真实模型

建立独立 `.venv-model`。按官方 Qwen3.5 与引擎文档确认支持版本，先执行版本与 `--help` 检查，在允许 GPU 上做最小模型加载。首选 Qwen3.5-4B，上下文 8192、单并发、输出上限 1600、非思考模式。任务短且采用显式结构状态，不直接复制官方超长上下文示例。

使用相同 checkpoint 的已验证本地目录或 4028 只读副本。下载须显式选择 Hub 并记录 revision。`validate_model_dir.py` 检查结构和 safetensors 文件完整长度，但不冒充官方全文件哈希验证。成功加载后记录模型清单、版本、dtype、显存峰值与服务命令。

## 阶段 4 完整闭环

启动 live API 与 Viser，执行 `live_smoke.py` 和 `live_interrupt.py`，再做场景协议中的未见表达测试。把同一 session_id 接入 Blender 桥接，确认两端跟随相同 DisplayPacket。保留三场景截图、B 到 C 再回 B 的连续视频、原始模型输出与事件日志。

需要输出 Blender 与 Viser 同时跟随同一状态的证据。无桌面时可用受限 CPU 的 Xvfb 或交互脚本加渲染帧验证，明确操作方式，不能用几张预生成资产图代替联动证据。

## 阶段 5 三次独立校验

修复后冻结实现，计算 source_sha256。三个独立 SubAgent 分别审查运行安全、视觉交互、架构与复现。每位独立读取最终代码、运行自己的检查并保存证据。三份报告写入 `runs/reviews`，通过 `scripts/check_review_gate.py` 后才能报告完成。该脚本只检查记录与证据完备性，审查真实性由实际 SubAgent 会话证明。

## 阶段 6 收官

保存 resolved requirements、最终命令、模型元数据、测试报告、真实截图与视频、内存记录、API 样例、未解决问题。提供可从用户电脑访问的 SSH 命令以及三进程重启方式。代码提交仅在用户仓库策略许可下进行，不擅自推送远程或改写历史。

## 停止条件

GPU 被占用、内存不足、模型文件不完整、引擎不支持、缺少必要权限、无法调用 SubAgent，都应明确暴露。可继续执行无依赖的安全阶段，但不能把整体任务标为通过。缺少光学标定属于后续接口工作，不阻塞阶段一的语义预览验收。
