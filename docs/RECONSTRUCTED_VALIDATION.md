# 重构版十二场景验证记录

本次在 4029 使用真实 Qwen3.5-4B / vLLM 0.29.0，按六批、每批两个新版场景完成有序任务、Viser 界面和同会话 Blender 桥接。端到端实验仅运行 `reconstructed`；`legacy` 保留独立入口。

## 场景与模型

模型运行于物理 GPU 1，温度 0.2、top_p 0.8、最大输出 1600、关闭 thinking；原生渲染保持 48 次采样。首批在 GPU 4 顺序采集，后续两场景分别使用 GPU 4、7。真实请求、回复、状态、确认完成记录、视频和原生分层图像保存在服务器项目的 `runs/simulation/reconstructed_qwen35_4b/`。

本地 `outputs/validation/runtime/` 是供查看的精简证据集，包含各层报告、关键截图和视频；完整原始数据及大型原生分层图以服务器正式运行目录为准。

Live API、浏览器审计与桥接审计各自使用独立会话。“同会话”指每组原生桥接中的浏览器状态与 Blender 消费记录；不同层的记录不拼接为一条连续轨迹。

首批 API 进程启动于状态库启动绑定修复之前，其已加载源码摘要未记录，因此不追认其属于最终提交。首批结束后重启至已提交代码，46 个空闲会话恢复后状态无差异，数据库绑定为 `reconstructed`。错版数据库拒绝写入由独立专项验证，活动任务重启恢复由后续故障实验验证；详细进程、Git 状态和加载边界见 `runtime_provenance.json`。

第二批的模型流程与 Viser 首次通过，但原生两路在第一帧前因 Blender 将相对 Python 入口解析到用户主目录而失败。提交 `220d602` 将资源守卫、桥接和导出器入口改为项目绝对路径；三个实际子进程路径回归在修复前失败，修复后相关 12 项测试通过。一次补跑的短命启动器被资源守卫结束时清理，未产生有效原生帧，记录亦保留。改由持续监督进程启动后，仅原生层在独立目录 `stage02_bridge_recheck_owned/` 完成。原 `stage02/stage.json` 仍为失败；`stage02/recovery_selection.json` 明确选用原模型、Viser、表面报告和有效补跑后的原生报告，包含原始证据摘要及尝试历史。表中表示修复后的完成状态，不表示所有尝试首次通过。

第三批货架首次界面采集在任务提交前失败：录像已出现货架画面，采集器仍查询旧输液会话。提交 `88cee71` 改为同时读取页面场景与会话，再校验 API 版本及同一客户端的新导出记录。两次补跑仍失败，均在任务提交前被 30 秒预算拒绝：第一次浏览器约 2.738 秒识别到新会话，Python 收回结果耗时 69.315 秒；提交 `36fe24d` 改用序列化字符串后，取值缩短为约 1.89 毫秒，但 Playwright 等待函数本身仍耗时 63.669 秒。浏览器内标识就绪不等于全部几何已显示，静止录像也不足以判断界面是否冻结。这三次失败及诊断记录均保留，未作为通过结果。

提交 `1d99cde` 将等待改为点击前安装的一次结构化浏览器事件，接收同一原子场景/会话记录，避开 Playwright 等待结果的额外浏览器往返。真实 Chromium 回归与相关 CLI、相机检查共 28 项通过；30 秒预算覆盖安装、点击、事件接收、API 和新客户端记录验证，迟到结果仍被拒绝。事件版真实货架补跑也在约 30.138 秒失败，未收到正确新会话事件。因而机制回归通过并不代表真实场景启动问题已解决；此后单独执行无任务、无模型请求的启动诊断，记录主线程长任务与页面身份变化。产品交互、模型及渲染参数保持原样，完整采集仍执行真实截图稳定性检查。`stage03/recovery_selection.json` 按场景明确选择原报告或补跑报告，并保留所有失败尝试。旧 API 日志的约 49 秒查询间隔不等于场景加载耗时，微型 DOM 诊断也不能反推原现场每段延迟的精确归因。

单次真实启动诊断中，正确身份在点击后约 4.3 秒已在浏览器内产生，但该事件交付 Python 滞后 66.714 秒。275 个浏览器心跳的最大间隔为 2.279 秒；观察器安装后开始的 288 个主线程长任务中，287 个在点击开始后开始，最长持续时间为 1.380 秒。这份证据不支持“界面冻结 67 秒”的判断，也没有定位具体传递环节。完整原始事件、视频和脚本保存在 `diagnostics/shelf_startup_timing/`。依据这次实测，提交 `6bc83a9` 为本轮后续采集增加显式 `--scene-ready-timeout 180`，单列启动等待窗口，保留工具原默认值与四次 30 秒失败；包含有限正数参数检查的相关 38 项回归通过。窗口覆盖观察器安装、场景选择、事件接收、API 和新客户端导出验证；模型请求参数、任务等待和确认语义、截图稳定性标准及 48 次采样均未调整。上表的界面通过表示在该明确配置下完成真实任务流程，不表示原 30 秒启动指标通过。

## 外观与交互

输液袋透明外壳在 Blender 全景中对比偏低，Viser 的袋体及部分反光表面仍能看到折面明暗。这两项外观问题未阻断本次已测试的交互流程，因此保留其材质和几何。Viser 检查视角中 BAG1/BAG2 的训练文字可读；Blender 原生图中的绿色检查提示圈会压低标签边缘字符的对比，不能宣称所有提示开启时的文字都清晰。两张相同检查相机的无提示原生补图中，TRAINING A/B、SIMULATION ONLY 和 ID BAG1/2 均清楚，说明该提示覆盖限制应与袋体透明度、折面明暗分别记录。补图沿用 48 次采样，未修改材质或源场景。推车前栏杆在 PUMPCASSETTE 普通特写下遮住底部部分实体标签，主体、侧边插槽及全景目标标注可见。

连接器移动终点的 Blender 绿色提示比 Viser 更浓，接收口和触点仍可辨认，但内部细节对比有所下降。确认完成后的最终实体位置正确、提示清空；这不消除提示开启时的显示限制。同相机、同对象和同提示数组的数值一致性，不等于两个渲染器的像素外观完全相同。

服务器维护的接收口也有相似限制：原生绿色提示更亮、更密，削弱内侧导轨表面的对比；左轨外轮廓、右侧支架与 SLOT4/4 标签仍可辨。检查接口时，提示圈覆盖外围局部孔和侧件，中央光纤接口及其文字保留。上述记录不表示所有内部结构在提示开启时均无遮挡。

光学平台的 POST2 终点提示覆盖安装孔，并向孔上方延伸；两种渲染器中，孔缘、侧锁紧螺钉与 POST 2 标记仍可辨。该提示开启视图不用于证明孔内表面细节完整可见。M 转台的灰白细刻度在两种渲染器中均对比较弱，顶部轮廓、调节螺钉与转台边缘可辨。

积木场景在两种渲染器的底面检查中，绿色提示环均横过 B 左右套筒的部分边缘；三个套筒位置仍可辨，中央套筒清晰，不能将该视图描述为所有表面均无遮挡。

积木与无人机的移动终点也出现原生提示云更浓的差异，分别降低底板目标凸点、电池仓底部及导轨细节的对比。电池仓小定位柱在原生图中较难辨认，外围、侧壁、前牌及部分长导轨仍可见；最终无提示图不用于消除提示开启时的这一限制。

无人机 GUARD 旋转起点、中点及终点的原生弧形提示更厚、更柔和，周围机架与紧固件的对比低于 Viser；中央金色面、白色索引和上缘缺口仍可辨。此时变化的是动作提示，GUARD 实体保持确认前姿态，已完成的 BAT 入仓位姿不变。

CNC 浏览器的目标特写和恢复后特写中，绿色旋转提示横跨 MANUAL 与 ATC 左部，降低这两处文字的对比；旋钮轮廓、中央指针和缺口、界面目标仍可见。T03 拉钉、颈部和六角环清楚，提示仅跨过更低的锥面。

CNC 旋转终点的原生图中，MANUAL 基本无法透过绿色弧读取，ATC 左侧明显变淡；中央白色指针、缺口和旋钮轮廓仍清楚。这是实际的文字识读限制，不能将当前任务流程通过扩大为所有视觉用途均不受影响。

CNC 的 T03 原生检查图采用灰金属和灰背景，其轮廓对比弱于 Viser 的黑色工具和白底；拉钉头、颈部和六角环仍可辨。这一渲染差异不能用两端相机及数值状态一致来替代说明。

发动机舱 PLUG 接收口在两种渲染器中均被绿色终点提示基本填满，深色圆形口沿和外侧宽法兰可辨，孔内部形状被覆盖。这是提示开启时的显示限制，不能据此判断几何堵塞，也不能据此宣称孔内部无遮挡。

CNC 的 POCKET9 接收口采集为偏侧面视角，09 字牌、外筒和法兰侧缘可辨，但上方孔内看不到，上方提示有裁切。确认后的无提示 T09 细节图在两端均显示刀柄下部与刀套上法兰的外表面对齐和贴合外观，09 字牌、环形法兰与螺孔可见；孔内部被已插入工具遮住，仍不作为内部接触证明。几何检查按后述独立范围报告。

默认规划器输入为文本与结构化场景状态，未传入渲染截图。因此本次结论适用于当前任务与交互流程，不外推为图像输入识别鲁棒性。动作终点先由提示表达；点击确认完成后，才提交实体位姿并推进下一步骤。

本次重新采集 24 张 Blender 图与 36 张 Viser 图，沿用最初审查的相机和截图尺寸。新旧对比为外观记录，不是新旧端到端对照实验。24 份新旧 Blender 文件的 440 个 FILE 图像引用均已内嵌，无所需纹理缺失或临时目录依赖。

考古场景的软件 WebGL 采集暴露出较慢的客户端准备过程：该次记录中，选择场景至服务端切换为 0.460 秒，观察到新 UI 会话为 108.441 秒，首次工作区视图事件为 127.970 秒，首张稳定截图为 256.167 秒。这些是一次采集的事件间隔，不是独立性能基准；原始失败与改为原子读取 UI 状态后的记录保留在 `visual/session_binding_review.json`，产品代码和模型参数未为此修改。

## 测试与几何范围

完整 pytest 初跑 761 项，其中 751 通过、10 项因场景目录前缀迁移失败。修复测试路径比较后，这 10 项与新增 11 项严格路径边界检查全部通过；固定 fixture、其他契约字段、几何断言和阈值保持原样。数据库绑定、GPU 授权、场景选择、桥接环境与表面标签分类另有针对性测试，原始 XML 和失败记录均保留。此后未重跑整套 761 项；各专项结果分别记录，不合并成新的全套通过数。

原有闭体几何检查仍为失败：18 条路径包含未闭合或面向不一致的障碍部件，无法满足其完整闭体覆盖条件。其已覆盖闭体部件上记录到 0 次穿透命中，不能据此推断未覆盖部件无碰撞。独立补充检查对真实三角表面和可用闭体执行有限位置采样，18 条路径通过；其 0.1 mm 容差和采样方法在报告内单列，不替代原有 41 × 1536 / 0.75 mm 闭体检查结果，也不证明连续无碰撞。

显示响应通过真实模型与界面固定相机、焦距、亮度，核对 Gaussian 数量及 σ 变化对应的实际画布变化。并发与故障检查覆盖两个客户端隔离、快速指令、在途取消、API 重启后显式继续、模型真实连接拒绝及显式恢复；过期数据检查使用实际版本门对保存快照回放，未宣称注入了网络迟到包。报告与视频分别保存在 `system/response/` 和 `system/resilience_faults/`。

故障测试结束时会停止其创建的 API，因此最终客户端截图可能再次显示连接失败；恢复成功依据停止前的显式继续、真实模型重试和状态记录，不将停止服务后的截图标作健康恢复画面。

## 版本入口

`scenes/legacy/<id>/` 和 `scenes/reconstructed/<id>/` 均包含 `scene.json`、`scene.blend`、`meshes/`、`docs/`、`reviews/`。旧网格和 Blender 文件来自 `aaf59d571d1cfda3038a004324356da136f2892f`，仅 JSON 路径和文档相对链接随目录调整。

运行使用 `bash scripts/run_simulation.sh api --scene-set reconstructed`，页面使用相同选择的 `viewer` 命令；改为 `legacy` 即选择原版。默认运行目录按版本分开，显式复用状态库时会检查绑定并拒绝跨版本数据。迁移时携带完整场景目录与共享 `assets/`，并执行 Git LFS 拉取。
